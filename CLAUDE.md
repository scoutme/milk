# milk

Switch models, not context. Routes prompts between a cheap primary agent (a local OpenAI-compatible inference server or any cloud provider) and a configurable escalation agent (Claude Code CLI or another inference backend), with session-aware state management and real-time streaming.

## Key design decisions

- **Unified agent config**: all backends — local inference servers and the Claude CLI — are entries in the `agents` array in `~/.milk/config.json`. Each entry has a `provider` field: `""` / `"local"` (plain HTTP), `"bedrock"` (AWS SigV4), `"claude-cli"` (Claude Code subprocess), or any string for Bearer-token providers. Auth transports: none (local), AWS SigV4 (Bedrock), Bearer token (OpenRouter, Together.ai, Groq, …), dynamic tokens via `token_cmd`, arbitrary extra headers. Bedrock also uses a native Converse API path (not OpenAI-compat). Tested: Qwen2.5-Coder 7B/3B, Gemma 4 E4B.
- **Bedrock credential renewal**: `aws_refresh_cmd` wires a `credential_process`-compatible command into the SigV4 transport; on 403 it refreshes credentials atomically and retries once, with TUI status-bar feedback.
- **Native MCP OAuth**: `/mcp auth <server>` runs milk's own RFC 9728/8414 discovery + RFC 7591 dynamic client registration + Authorization Code/PKCE flow (`internal/mcpauth/`) — no Claude CLI hand-off. TUI stays interactive: local loopback listener, best-effort browser open, URL also printed to the transcript, status-bar "MCP OAuth: `<server>`" indicator. Tokens in `~/.milk/mcp_oauth/`, refreshed proactively before expiry and reactively on 401.
- **Unified MCP auth resolution**: `internal/mcpauth.ResolveHeader` is the single auth-resolution path (`bearer` / `token_cmd` / `oauth`) shared by every agent that builds MCP request headers — `internal/mcp.Client` (local/primary agent) and claude-cli's `--mcp-config` generation (escalation agent) both call it. A server needs authorizing once regardless of which agent(s) use it; fixes a prior gap where `token_cmd` was silently dropped for escalation-agent MCP servers.
- **Three-source permission asks** (`cmd/milk/permask.go`, ADR-0052): every permission ask races direct input, remote oversight, and — for background asks only (job/workflow tool prompts, doom-loop confirmations in unattended contexts) — a *timed answer* that applies the configured default (`permissions.*`, default deny after 360s) at the deadline. Background asks surface to the main TUI prompt queue (countdown, `a`/`d` bulk answers, queue cap) instead of failing closed; `oversight.Notifier.AskPermission` returns `(decision, answered)` so silence is never mistaken for a reply; `/permissions` shows and session-overrides the policy. Questions (the `ask_user` tool, issue #249) ride the same layer (`askUserQuestion`) with free text instead of y/n and a timed *no answer* instead of a timed default — TUI free-text prompt queue (bulk keys disabled), ACP one-field form dialogs (form-capable clients) or the typed-chat answer floor otherwise (next message is the answer — `cmd/milk/acp_askchat.go`, issue #266), Telegram free-text replies via `AskInput`; silence never answers a question, and unanswered ones return guidance, not errors. Session stickiness (issue #302): at any tool prompt `a`/`d` answers it *and* adopts `allow-all`/`deny-all` for the rest of the session (`Allow? [Y/n/a/d]`, `[perms: …]` status bar, `/permissions mode …`, ACP *Always allow*/*Always deny*, sticky Telegram replies through the ask-policy `sticky` hook) — tool asks only: the doom-loop safety gate keeps prompting, `ask_user` questions are never auto-answered, and the mode runs before the grant store, so no persistent grant is ever written.
- **Layered context reduction** (ADR-0058, issue #236): small windows get dynamic relief before history is touched — as request pressure (prompt tokens ÷ window minus output reserve, the same denominator as `compaction_trigger_tokens`) climbs past the per-agent `context_reduction` thresholds (55/65/75, `mode: "off"` restores prior behavior exactly), the static layers shed in value-per-token order: system-prompt tier steps down and optional guidance drops (instructions), then tool descriptions are one-lined and the AGENTS.md block trimmed, then the tool set is pruned to tools observed in use plus `protected_tools` — with existing history compaction/drop-oldest staying deeper and unchanged. Recomputed request-scoped at every tool-loop iteration (`internal/contextreduce`, `internal/agent/local/reduction.go`) — session state is never mutated, so layers ease back by themselves after a compaction. Local agents only (background jobs get the tool-side layers); custom `prompt`/`prompt_file` and percepts/current-need are never dropped; `milk.inference.context_reduction{layer=...}` counts when a layer is live.
- **Local-agent toolset hardening** (2026-10-19, `docs/internal/analysis/local-agent-toolset-review.md` phases 1–4): tool batches run under a **barrier model** — consecutive pure reads parallel, everything else ordered, a failed write/bash cancels the rest (ADR-0062); every path-taking tool and `bash` resolve relative paths against the *session* cwd (ACP `session/new` can differ from the process cwd); `read_file` `offset` is 1-based; `edit_file` has a fuzzy fallback chain (line/whitespace/indentation/escape tolerant) that only ever applies unique matches and otherwise returns a closest-match hint, with CRLF preserved and atomic writes; `grep` is ripgrep-first (`ignore_case`/`context`/`include`/`max_results`, `grep -E` fallback) and `find_files` supports `**`, honors `.gitignore`, caps and sorts newest-first; `bash` gained `workdir` and `run_in_background` with `bash_output`/`kill_bash` (ADR-0063: outlive the turn, killed at process exit, 16-shell cap, 1 h auto-kill; ADR-0064 surfaces shells in the one merged background panel — click-to-attach rows, `/bg` on both kinds of IDs — and as ACP tool-call rows with streamed live output); `web_fetch` (HTTPS upgrade, HTML→Markdown, format/max_bytes, spill) replaces `http_get` (kept as a dispatch alias) and per-agent `post_edit_command` appends formatter/compiler output to every successful edit/write result. Phase 5 follow-up (issue #251): `multiedit(path, edits)` applies several edits to one file in a single all-or-nothing call over the same fuzzy chain — each edit sees the previous one's result, any failure writes nothing, and the batch is one permission-gated, barrier-ordered write.
- **Local-agent prompt caching**: two independent mechanisms, both feeding the same `TokenUsage.CacheRead/CacheCreation` → status bar/memory panel pipeline. (1) OpenAI-compatible implicit caching — parses `usage.prompt_tokens_details.cached_tokens` (OpenAI's own standard field, mirrored by e.g. Xiaomi MiMo) with zero request-side changes or config; live-verified. (2) Bedrock explicit `cachePoint` caching — opt-in via `prompt_caching` in the agent config entry; up to 3 breakpoints: one anchored right after the stable system-prompt prefix specifically (not at the end of the `system` array, where it would otherwise get bundled with — and invalidated by — per-turn percepts/current-need entries that follow it), plus a rolling double-buffer over the last two conversation messages; **experimental, not live-tested** (no Bedrock agent available during development). Provider-reported prompt-token totals that include the cached portion (subset, not additive) are normalized to fresh-only before recording — see `internal/agent/local/local.go`'s `streamCompletion`.
- **Throughput (tok/s) measurement**: per-request streaming timing — TTFT (request send → first output delta) and the decode window (first → last output delta, deliberately excluding between-request tool time) — captured where each provider's stream is parsed (`internal/agent/local` `scanSSE`/`scanResponsesSSE`/bedrock event loop → `StreamTiming` on the `onTokens` hook; claude-cli instead parses Claude Code's own `duration_api_ms`/`ttft_ms` result-event fields). Aggregated per turn and per (model, role) into `session.TokenUsage.{DecodeSeconds,TTFTSeconds,Requests}` and `obs.RecordTiming`, surfaced as the TUI status bar's tok/s/TTFT fragments, `/usage`'s `tok/s` column, and the stream-json result event's `output_tokens_per_second`/`ttft_ms`. Generic subprocess agents (aider/smolagent) have no timing source and render `—`, never a fabricated 0.
- **Single inference server instance**: same server handles both router classification and local coding/tool tasks
- **models.dev context-window fallback**: `Config.AgentContextWindowTokens` falls back to a best-effort lookup (`internal/modelsdev`) against the [models.dev](https://models.dev) catalog when an agent entry omits `context_window_tokens`, matched case-insensitively against the agent's `model` string across every provider in the catalog (milk stores no models.dev provider ID). Since a model's context window essentially never changes once published, the primary source is a catalog snapshot embedded at build time (`internal/modelsdev/snapshot.json`, regenerated via `scripts/update-models-dev-snapshot.sh`) — works fully offline, zero startup latency. A live fetch, cached to `~/.milk/models_dev.json` and refreshed in the background past a 24h TTL, is only a fallback for a miss against the embedded snapshot (e.g. a newer model); served from memory, so a lookup never blocks a turn. Explicit `context_window_tokens` always wins over either source. `disable_models_dev_lookup: true` turns off both the embedded and live lookup (e.g. a custom/fine-tuned model sharing a name with a catalog entry). Documented under `docs/guides/providers.md`'s "Context window declaration" section, which `internal/selfdocs` also exposes to any agent via the `models.dev`/`context window` topic aliases — so milk's own agent can answer a user's question about a model's context window using this mechanism.
- **Escalation agent**: any `agents` entry can be the escalation target — set `escalation_agent` to its name. Defaults to the built-in `claude-cli` entry. Use `/agent switch <name> as escalation` to change it at runtime.
- **ACP session parity (resume-by-default + standard chat history)**: over ACP, `session/new` adopts the cwd's most recent stored session (the TUI's `--continue` default; opt out via `acp_resume: false` or per-request `_meta.milk.fresh: true`), `session/list|resume|close|delete` are implemented, and chat history replays via the ACP v2 standard message upserts (`replayFrom: {"type":"start"}`; deterministic `hist-*` IDs so re-replay patches instead of duplicating, runID-suffixed live IDs so nothing collides across restarts), bounded head+tail with a gap marker pointing at `/export`. `/export session <id|prefix>` previews another session without attaching. Exports include reasoning deterministically (`<reasoning>…</reasoning>` fences in text, `thinking` fields in JSON — session data only, so TUI fold state never leaks in; 8 KB head+tail budget per block), stripped with `--no-reasoning` (issue #277). See docs/reference/acp-integration.md.
- **ACP conversation views (session slash commands + view rebinding, ADR-0051)**: the one in-chat session vocabulary — `/sessions [all]` (renamed from the ambiguous `/list`; `/list` kept one release as a hidden deprecated alias), `/new`/`/clear`, `/resume <id|prefix|name>`, `/drop [<ref>]` — runs on both the TUI and ACP through the host-neutral `sessionmgmt_core.go`. Over ACP the wire handle is fixed (session/resume's response carries no sessionId), so an `acpSession` is a *conversation view*: `/new`/`/resume`/`/drop` rebind its store session in place (session-scoped state follows the binding, view/user state survives), every switch replays bounded history with a notice, a store session is bound by at most one live view, replay IDs become session-qualified after a rebind, and `session/resume` resolves binding → handle (rebind back) → new view with alias handles. See docs/adr/0051-acp-conversation-view-rebinding.md.
- **Claude via CLI subprocess**: `claude --print --output-format stream-json`, not direct API. Configured as `provider: "claude-cli"` in `agents`.
- **Background sub-agents** (ADR-0043): any inference-server-backed agent (primary or escalation — the deciding factor is provider, not role) can call `spawn_background_agent` to fork an independent copy of itself for a self-contained research task with its own tool loop, running asynchronously via `internal/agent/local.Manager` and reporting back on the next turn (`dispatch.go`'s `drainBackgroundJobs`) plus immediately in the TUI — a toast for the lifecycle notice, and the job's result itself appended to the transcript the moment it exists (`cmd/milk/background_ui.go`; capped to the model's delivery budget, `/bg show <id>` prints it in full), so a result can't pass by unseen just because the model never reports it. The local-agent analogue of Claude Code's own fork/Task tool; `claude-cli` needs no equivalent since it already has that natively. Long-running jobs get a soft deadline (ADR-0068, issue #271): at 80% of the job timeout the job is messaged to stop exploring and write its final answer (`<result status="partial" …/>` if incomplete), and one that still hits the hard timeout salvages its last assistant text alongside the tool trail.
- **Shared workflow board** (`internal/workflow/board`, ADR-0071, issue #197): a definition's `board: true` flag gives the run a mutex-protected, write-through sidecar board (`<checkpoint>.board.json`) every stage renders as `{{.board}}`; local-provider roles get per-call `board_get`/`board_claim`/`board_update`/`board_post` tools (ctx-gated registration, `role·Item-N` identity, CAS claims — the one thing parallel_group items deliberately share, per #297's no-shared-mutable-state rule; CLI roles are snapshot-only), `board_seed` turns the plan's `## Item N (depends_on: …)` sections into items idempotently, and `ParseVerdictKey` lets a stage's `verdict` map declare its **own** response words (team's `all_done`/`more_work`) with the three historical keywords kept as fallback. `team` (definitions/team.yaml) is the built-in consumer: swarm's shape plus claims, findings and a coordinator stand-up — no interpreter branch ever keys on a workflow name. Live-run follow-ups ([ADR-0073](docs/adr/0073-team-live-run-fixes.md)), all generic and driven by definition fields: `parallel_group` schedules per item (dataflow, not waves) and `skip_if_board_status` re-runs only reopened items on a repeated fan-out (settled items keep their last result); a verdict rule's `board_status` reopens the current item on a retry so its re-claim isn't refused; board item labels are de-markdowned, repeated `board_post`s absorbed, and workflow turns' usage is attributed per workflow role (`primary:workflow:<role>`).
- **Side-panel auto-open** (ADR-0044, override lifecycle amended by ADR-0059): tasks, background-agents, and workflow panels open themselves the moment their content becomes active (a task created, a background job spawned, a workflow started) via `(*model).autoOpenPanel`, but a manual `/panel <name>`/F-key toggle (`model.panelManualOverride`) sticks over automatic management while the panel's content stays live, in either direction — the override drops again as soon as the content finalizes (`panelContentFinalized`: all tasks done, no running jobs, workflow done/cleared, store emptied — via `resetManualOverrideIfFinalized`, called at close time and on each finalization event), so the next new content auto-opens the panel again, and closing an already-settled panel never records one. Panel titles show their F1-F6 hint (`panelTitleLine`); every other currently-open panel (by visible left-to-right position, not fixed per region) gets a subtle background tint (`panelAltBackground`), with `withPanelBackground` re-applying the tint after every embedded ANSI reset so it survives behind already-styled badges/titles/dim text instead of being wiped by their own reset codes.
- **Idle tip line** (ADR-0061): one dim `tip:` line in the hint region below the input (the `tabHints` slot — it yields to completion hints; `(*model).hintRegion` is the single line-count source both `View` and `viewportHeight` use) surfaces the feature surface while the user is idle. Contents by precedence: contextual hints computed per render (no agent configured, update pending → `/update install` with the release tag), then curated priority-ordered one-liners, then tips derived from the slash-command registry (`registryTips`: every non-hidden TUI command a curated tip doesn't name gets `{/name <hint>} — desc` from the registry's own `desc`/`hint`, rendered host-aware via `hintFor(hostTUI)` — `/think`'s tip shows its fold vocabulary while ACP advertises `[on|off]` — so tips can't drift from the command set; `buildCmdVariants` skips help lines annotated `ACP only` so TUI completion never offers arguments the TUI rejects). Rotation (`tipsTick`, 20s) cycles `buildTipList()` deterministically and freezes while a turn runs or a prompt is pending; `/tips [on|off]` toggles and persists to config `show_tips` (default on). Tips are browsable: `/tips next|prev|pick [<n>|<text>]|search <query>` and the global `Alt+Up/Down` shortcuts step through the pool (the rendered line references the shortcut via `tipNavRef`; a manual browse restarts the cycling timer — `tipsTickMsg.gen` vs `tipsGen`, the toastTickMsg pattern — pins the rotation's entry over contextual hints until the next automatic advance, and echoes to the transcript while the line is hidden).
- **Notification toasts** (ADR-0048): turn-unrelated informational events (`/think expand|collapse` state changes, panel toggles, ADR-0044 auto-open transitions, background-job lifecycle, config reload, MCP OAuth/credential refresh) render as a floating timestamped toast overlay pinned to the top-right of the main area — a pure render-time overlay consuming zero layout rows (viewport/panel/PTY geometry untouched) — instead of the transcript. Each toast carries its related slash-command hint (fallback `/notifications`); events queue (max 3 visible, fresh 6s TTL on promotion) and never expire unseen; history ring (500) is browsed via `/notifications [clear]`. Dismiss interactively with **Ctrl+G** or let them time out — dismissal keeps history. The expiry tick is generation-guarded (the #168 lesson). Scope boundary: tool calls, turn-bound output, warnings and errors stay in the transcript.
- **Project tree + git graph panels** (ADR-0066, issue #206): `/panel project` (F5) shows the cwd's file tree from the `@`-completion file index (git-backed, walk-budget-safe) — click a dir to expand/collapse, a file to preview it in the main area (attach view, `attachPreview`), double-click to insert an `@`-mention; `/panel git` (F6) shows the commit graph with lanes laid out in code from `git log` parents (`layoutGraph` — no `--graph` ASCII parsing, rows carry their hashes structurally), branch + dirty count on top, click a commit for a capped `git show` preview. Both tick-refresh (3 s) off the UI goroutine into model-cached `lines`/`ids` arrays (View renders a value copy — caches are never written on the render path), never auto-open, and degrade gracefully outside a git repo.
- **Live-attach view** (ADR-0047): double-clicking a background-job or background-shell row (F3; ADR-0064) or the workflow panel (F4) swaps the main transcript viewport for that job's/workflow's own `internal/livebuf.Buffer` (`model.attached`, `cmd/milk/attach.go`) — its tool calls and streamed text, kept off the main transcript the whole time — modeled on the existing `m.ptyPane` viewport-substitution pattern but with side panels staying visible; Esc detaches. Fixed a real bug in the same change: `workflow.WorkflowChunkMsg` previously leaked stage output straight into the main transcript; it now accumulates in `workflow.State.Live` instead. Claude CLI's own Task-tool subagents and background-workflow `journal.jsonl` remain out of scope — no content is exposed via `stream-json` for the former, and the latter's schema is unverified.
- **Context handoff**: local transcript passed to a new CLI session via **one** `--append-system-prompt-file` flag holding the static instructions and dynamic summary concatenated — the Claude CLI only honors the *last* such flag when more than one is given, so a literal two-flags approach (as ADR-0004 originally specified) silently drops the first; corrected 2026-09-30, see the ADR's Update section. On `--resume` Claude Code replays its recorded system prompt (`--system-prompt-snapshot`) and ignores new files until a compaction, so per-turn context is prepended to the prompt in a `<milk-context>` block instead (full static block still passed as a file, re-recorded on compaction); local providers receive a `BuildDynamicContext` orientation block as a prepended system message. Both paths inject percepts on `First`/`Returning` turns; a percept recorded mid-resume is also re-surfaced via a small diff block on `Resume`/`Continuation` turns rather than waiting for the next `First`/`Returning` turn. On stale returning escalations (topic switched or ≥`returning_fresh_start_local_turns` local turns since last escalation, default 8), CLI drops `--resume` and local providers scope history to post-escalation turns only.
- **Confirmation-aware routing** (ADR-0065, issue #263): a short "proceed / go ahead / yes / do it" prompt is routed on the **resolved confirmed content** (`internal/router/confirm.go`) instead of its bare text — the scope the prompt adds ("yes, do the big refactor" → `do the big refactor`), else the last agent message when it proposes new scope ("want me to also rename X?" per `rules.confirmation_new_scope_markers`), else the last non-confirmation user message (chained confirmations walk back; a tail-bearing one contributes its scope). User words bind on their escalate markers (marker-aware shortcut replaces the unconditional `local_below_tokens` local for this class), agent-authored scope routes exactly as the same text would typed directly, and everything else is the ordinary rules layer on the resolved text (classifier gets the resolved content, not "proceed"). Over-escalation guard: small new scope stays local even mid-hard-session. Pinned/sticky/`ESCALATION_WAITING` turns bypass the router first and are unaffected. New `rules` knobs: `confirmation_phrases`, `confirmation_new_scope_markers` (English + Italian defaults).

A response can carry many calls: `Extract` parses everything after the opening delimiter (parallel `<tool_call>` tags, one fence per plan step, one bare object per line), and `parseToolCallsJSON` reads a body as a stream of JSON values — several objects, an array, raw newlines/tabs inside strings (escaped before parsing); a truncated last call is dropped, a non-call value (config example) skipped. The opening delimiter must still start at a token boundary to be detected in-stream (otherwise the post-hoc scan finds the calls, with the raw JSON already shown).

Blocks are folded by default at all times — streaming ones included, no auto-open (long reasoning doesn't flood the transcript): while reasoning streams in the folded header's line count updates live. A new block keeps the folding status the previous one was left in (`model.thinkFoldOpen`, set only by explicit fold actions), and a new turn collapses the previous turns' blocks (`collapseThinkBlocksBefore`) — but only while that status is folded: `/think expand` defines the current default and opts the tidy out entirely; the tidy never changes the status itself. Click a header — or **Ctrl+T** for the most recent block (the streaming one, if any) — to toggle just that block (`userSet` pins it against the close: a block opened mid-stream stays open when streaming ends); `/think expand|collapse` pin all blocks, `/think view` swaps the main area to a thinking-only stream (attach preview). Streaming renders must stay stable: `transcriptDisplayAt` reports where the open block's container begins and `wrappedTranscript` never commits its colorize cache past that boundary (the container is re-rendered per chunk — live count + per-line surface styling — so a committed prefix would garble the streaming lines). There is no hidden mode and no placeholder rendering: every block always shows its header row; `/think on|off` were removed with the fold model. The ACP `think` option / config `show_reasoning` is the data-plane relay toggle (whether `agent_thought_chunk` updates leave the process at all) and is independent of TUI fold state. Loop detection, the session turn record and the ACP thought relay consume reasoning independently of display. The *starting* fold status is the explicit config knob `think_fold_default` (issue #278): unset/`folded` = today exactly; `expanded` seeds each session — blocks arrive open, the turn tidy is opted out from the start, a `/resume` switch re-seeds — while per-session actions still win and `show_reasoning` stays untouched (seed + action precedence tested).
- **Self-contained wrapped rows** ([ADR-0072](docs/adr/0072-self-contained-wrapped-rows.md)): a word wrap can split a styled span across rows, but viewports, per-row tints, truncation and selection treat rows independently — so every wrap of styled transcript content goes through `wrapRows` (`ansi.Wrap` + `sgr.SelfContain`: each row re-opens the inherited SGR state and closes at its end). `internal/sgr` is the one SGR model (`State`, `Walk`/`Scan`, `WithBackground`, `LastBackground`, `Highlight`); the think/diff painters, selection highlight, `applyInlineMarkdown`/`splitTurns` carry and the colorize-cache seams all build on it instead of tracking "the last escape code" themselves. New code that wraps styled text calls `wrapRows` and needs no state tracking of its own.
- **Full-row diff backgrounds** (issue #273, [ADR-0069](docs/adr/0069-full-row-diff-backgrounds.md)): inline edit diffs (`internal/diff`'s +/- rows, 256-colour 22/52 backgrounds) paint the background across the whole row, not just the glyphs — `tintDiffSurface` (`cmd/milk/diffsurface.go`) recognises diff rows by SGR state after wrapping and pads them to the viewport width with the pad inside the background; `tintFullRows` applies it together with the think painter at every render site (the five `wrappedTranscript` returns and the attach view, before `tintBlock`). Emission is untouched: the pad is appended *after* the row's reset (close-then-reopen, so nothing inherits green/red across the `\n`); wrapped continuation rows are self-contained (ADR-0072), so every row of a long +/- line gets that same treatment. Recognition is tight — only colours 22/52, never arbitrary backgrounds; chroma-highlighted diff fences are foreground-only (nothing to pad) and colorize full (glamour) still strips diff colours (pre-existing, separate gap). Render-time only: buffers, colorize cache and the plain coordinate space unchanged; `transcriptPlainLines` trims the pad
- **Project instructions**: the primary/local agent loads the target repo's own `AGENTS.md` into its system prompt (falling back to `CLAUDE.md` when no `AGENTS.md` exists, since a local model has no other path to it), the same way Claude Code loads `CLAUDE.md` and OpenCode loads `AGENTS.md` (`internal/instructions`, cached by mtime). The escalation agent's static context (`internal/escalation`) also injects `AGENTS.md` — but never `CLAUDE.md`, since the Claude CLI subprocess already loads that natively. Opt out per agent with `disable_project_instructions: true`.
- **Current date injection** (ADR-0060): LLMs only know their training cutoff, so milk renders `Current date: <ISO date> (<weekday>), local time zone <name> (UTC±HH:MM).` (`escalation.DateLine`, `internal/escalation/date.go`) and injects it into every agent's system context itself — right after `identityBlock` in `BuildStaticContext` (all four `ContextMode`s and both instruction gates; covers Claude-CLI escalation and the aider/smolagents primaries via `BuildPrimaryStaticContext`) and in the prompt core of `buildSystemPromptOpts` (every tier incl. `minimal`, every role incl. workflow, survives the ADR-0058 reduction ladder). Both builders re-render per turn from `time.Now()` so a session crossing midnight self-corrects; the line is deliberately date-granularity (no `HH:MM`) so cached prompt prefixes (Claude's cached prefix, Bedrock `cachePoint`) invalidate only at midnight/DST, not every turn. The `date` shell tool remains the precision fallback.
- **Context compaction**: when message history exceeds budget, `trimLocalMessagesWithCompaction` (`cmd/milk/main.go`) makes one extra inference call (`Agent.Summarize`, a plain tool-free completion) to summarize exactly the span that would be dropped, splicing the summary in as a single message instead of discarding it outright. Falls back to the old plain drop-oldest-first trim when there's nothing to summarize, the call fails, or the provider doesn't support it (Bedrock, Responses API). Opt out per agent with `disable_compaction: true`. A *running* turn also compacts itself (`runToolLoop`): when the previous request's provider-reported `prompt_tokens` reaches `Config.AgentCompactionTriggerTokens` (85% of window minus an output reserve — models.dev output limit capped at 32K, 20K default, ≤ ¼ window; override `limits.compaction_trigger_tokens`), the older half of the turn is summarized (`compactForPayloadSize`; the summarizer sees tool calls plus 2000-char result heads, and the summary ends with a `<files-touched>` list). The 900 KB request-size trim is now only a proxy safety net and follows the window (~4 bytes/token) above that. Tool results are capped per agent at ~10% of the window clamped to 4–50 KB (`AgentToolResultMaxByteCount`), and a capped result's marker says how to read the rest — for everything but `read_file` (whose source is already a file) the full output is first saved to `~/.milk/tool-output/` (mode 0600, swept after 7 days, `local.spillToolOutput`) and the marker names that path so the model can `grep` / `read_file` it instead of re-running the command. Prior art: OpenCode / MiMo-Code / Claude Code (see `docs/internal/analysis/prompt-context-management-review.md`).
- **Tool trail between turns**: a local-provider agent's tool calls and results are stored with its assistant turn (`session.Turn.Trail`, captured by `local.TrailFromMessages` in `runToolLoop`, bounded at capture: 8 KB per result, 256 KB per turn) and replayed to that same agent on later turns by `buildAgentHistory` (`local.ReplayTrails`): the newest 2 tool-using turns as real call/result messages with output kept newest-first up to 160 KB (older results become `[Old tool result content cleared]`, the call and short arguments stay), older turns as a one-line manifest (`[milk] tool activity in that turn: read_file ×12, …; files: a.go (edited), …`). Before this only the final text survived, so a follow-up turn re-read what the previous one had just read. Never shown in transcripts, ACP replay or `/export`, never handed to another agent (those use `Content`) — but models sometimes ECHO the manifest format into their replies (it is in their replayed context), so the transcript render dims any line-leading plain `[milk] …` (and the pre-#270 `[Tool activity in that turn: …` form) to the standard tag via `dimMilkAnnotationRows` inside `tintFullRows` — render-only, stripped again for selection/copy. Reasoning is not stored (MiMo accepts tool-call history without it — live-checked).
- **Bash permission pre-approval**: `bash_allowed_patterns` (per agent) is a static allow-list of bash command prefixes (`"git status*"`, exact match with no trailing `*`) that skip the permission ask/grant entirely, checked before the normal `PermStore`/interactive-ask flow — a finer-grained, purely additive complement to a blanket `bash` grant, not a replacement for it.
- **Background sub-agent enhancements**: `spawn_background_agent` gained `full_context` (opt-in; injects the spawning agent's already-capped `sess.LastLocalSummary` as extra orientation for a job whose task genuinely depends on the caller's recent activity — not a raw conversation snapshot, which would reopen the cost risk isolation exists to prevent) and an optional structured result convention (a job's answer may end with `<result status="ok|error|partial" files_touched="..."/>`, parsed by `drainBackgroundJobs` instead of requiring prose parsing). `cancel_background_agent(job_id)` is the model-facing counterpart to the human-only `/bg stop`. - **Undelivered tool calls** (`internal/agent/local`): some OpenAI-compatible servers (observed: MiMo) fail to parse a model's tool call mid-stream and leak it as `<tool_call>=name><parameter=…>` text in `content`, reuse one stream index for several calls, or send a call's arguments before its id/name. `accumulateNativeToolCalls` opens a new call on every fresh `id` (dropping nameless orphan arguments, repairing a dropped closing brace only on a call the server visibly moved past); a response that claims `finish_reason: tool_calls` yet yields no runnable call is hidden and retried up to `maxMalformedToolCallRetries` times with a nudge; before any retry, `recoverLeakedToolCalls` (`toolrecover.go`) turns the leaked text back into a real call when the response ended `finish_reason: tool_calls` and the tool name is in the request's tool list, the parameters validate against that tool's schema, every value is corroborated by the nameless argument fragments the server streamed for it, and the call wasn't already delivered natively (each recovery is logged at WARN in `milk.log`); if neither recovery nor retries work, the leaked markup is replaced by the tool trail (`stripUnparsedToolMarkup`, trail capped at `maxToolTrailChars`) so session history stays clean and records the turn's work.
- **Action turns and between-turn events in history** (`cmd/milk/turn_record.go`): a turn that ends without closing text but did something (`start_workflow` launch, spawned job, any tool calls) is stored as an assistant turn with its `Trail` and a generated note (`recordSilentTurn`; `actionNotes` gives per-tool wording, everything else is summarized as `tool ×N`), so the next turn's model sees its request as answered instead of repeating the action. A failed/cancelled turn is kept only if it changed something that outlives it (an `actionNotes` tool or a side-effecting tool call — see the request-level retry bullet below); otherwise history stays untouched so a retry doesn't trip the repeated-prompt escalation. Events outside any turn — a workflow finishing (`noteWorkflowFinished`, TUI + ACP) — queue in persisted `Session.PendingNotices` and ride the *next* user turn as a `[milk] …` prefix, both in the prompt and in stored history (completed background-job blocks are stored the same way, bounded), which keeps user/assistant alternation intact and needs no new turn role.
- **Remote busy indicator** (issues #284/#286, `internal/oversight/telegram`): while a turn runs, its 🔄 turn-start message carries a status line **edited in place** — `💭 thinking…` (reasoning/tools), `⌨️ typing…` (response streaming), `⏳ waiting for you…` (a remote ask is open) — elapsed counters ticking on the render interval, state changes rendered immediately, and the line **stripped at turn end** so nothing permanent lands in the transcript. The native `sendChatAction("typing")` runs only while text streams (rate-limit-safe ≥5s cadence — the pre-#286 4.5s one 429'd itself), where its fixed label is accurate and as the fallback when the turn-start message id never arrived. Depth/stack-tracked across overlapping turns (TUI runTurn, ACP dispatch and the workflow runner pair `NotifyTurnStart`/`NotifyTurnDone` on every path; LIFO — a rare out-of-order end can silence a line early but never restore the wrong message), renders refused after `stopStatus`'s `done` flag so the async restore can't be re-overwritten, 429s honor `retry_after` and a deleted message goes `dead` gracefully; `remote_oversight.busy_indicator` (default `true`, independent of `notify_tools`) opts out, and non-turn notices route through `notifyAnnouncement` → `Announce` (same 🔄 message, no indicator).
- **`/interrupt`** (issue #288, `handleInterruptCmd` + `prompt()`'s pre-`turnMu` intercept + `acp_oversight.go`'s `remoteInterrupt`): the Ctrl+C equivalent (`cancelTurn` + `interrupted` → `[interrupted]`) reachable on every surface — TUI (incl. busy-Enter via `busySafeCommands`), Telegram remote input (routed **around** the busy queue, and around dispatch when idle — never model text), ACP prompts (intercepted before `turnMu`, so it can't queue behind the turn it cancels; native `session/cancel` unchanged). **Recognition is the shared first-token rule** (`extractSlashCommand`): only an input *starting* with `/interrupt` (exact or with trailing words) cancels — mid-input occurrences and lookalikes are plain text on every surface. Interrupted turns notify remote oversight as `⏹ turn interrupted` instead of a `❌` error (`telegram.NotifyTurnDone`'s `context.Canceled` case, plain or wrapped).
- **Quiet tool styling in Telegram** (ADR-0070, issue #290, `telegram.go`'s `toolUseMessage`/`toolResultMessage`): the TUI dims tool hints (ADR-0026) and Telegram has no dim, so tool lines become single-line tags — italic name + inline-code summary (`» _Bash_ · \`…\``), **error results stay bold** (`❌ *Bash* error · \`…\``). Summaries flatten (newlines → ` ⏎ `) and cap rune-safe (use 200 / result 497) so the unchunked tool send can't hit the 4096-unit limit; code content escapes only `\` and `` ` `` per MarkdownV2's in-code rule (`escCode`), while the italic name keeps full `escMD`.
- **Claude is never reached without approval unless configured** (ADR-0055, `cmd/milk/fallback_core.go`): when the escalation target is only the built-in Claude default (`Config.EscalationAgentIsImplicit`: no `escalation_agent`, no `claude` entry), every route to it asks first — a down primary, an explicit `/escalate`/`--escalate`, a pin, sticky or router escalation, and the model's own `escalate()` (`gateClaude`, `confirmSelfEscalation`). Default No, once per session (`interactiveState.claudeApproved`), through the ADR-0052 ask layer (TUI prompt, ACP dialog, Telegram); single-prompt asks on a TTY or refuses naming `escalation_agent`. An approved outage fallback does not make escalation sticky. `escalation_agent: "claude"` (or a `claude` entry) makes it a configured agent and removes the question.
- **Request-level retry and stall watchdog** (`internal/agent/local/stream_retry.go`): a transient HTTP/2 error (stream reset, GOAWAY) or a request that gets no SSE `data:` event for 5 minutes (keep-alive `: PROCESSING` comments don't count — a ~490K-token request was seen held open that way until the upstream reset it) re-sends only that request from `runToolLoop`, with the turn's messages intact. `executeWithRetry` (`dispatch.go`) never restarts a turn that already ran a tool: its results live only in the failed run while its edits are already on disk, so a restart re-planned from the bare prompt and found its own earlier edits as "someone else's partial work". A failed or cancelled turn that changed anything (`local.SideEffectingTool`: edit/write/bash/…, or an `actionNotes` tool) is now recorded with its tool trail (`recordInterruptedTurn`); a read-only one still leaves history untouched so a retry is clean.
- **`ctx:x/y` is one request, not the turn sum** (`obs.RecordRequestInput` / `SessionLastRequestInput`): a tool-loop turn re-sends the whole conversation on every request, so the per-turn token delta is a multiple of the context size. Local-provider agents record each request's total input (fresh + cached) under their exact role; `logRole()` gives tool-agent and workflow clones their own `:toolagent` / `:workflow` buckets so they never feed the plain role. The idle status bar uses that value and falls back to the turn delta only for providers that don't report per request (claude-cli, generic subprocess agents — their ctx figure can still overstate). Counter deltas clamp across session swaps (`counterDelta`).
- **Workflows run in the background** (`cmd/milk/workflow_cmd.go`, `repl.go`): launching one — by `/workflow` or the `start_workflow` tool — no longer sets `busy`/`cancelTurn`. It has its own `workflowRunning`/`cancelWorkflow`/`workflowGen` (the idle-watchdog tick carries the generation so an old run's tick can't start a second chain), so an agent turn and a workflow never clobber each other's state (`WorkflowDoneMsg` touches neither `busy` nor the turn counters). Input rules: a free prompt throughout; `/workflow status|cancel` are busy-safe, every other `/workflow` subcommand and the session-switching commands are refused while one runs; Ctrl+C cancels the turn first, and at an idle prompt arms the quit confirmation (status bar says a workflow is running) instead of silently cancelling the workflow; pending designer questions take the next Enter even mid-turn and Ctrl+C then cancels the workflow. Fixes the tool-started path, where the originating turn's `agentDoneMsg` used to wipe `cancelTurn` (no way to cancel) and stop the idle watchdog.
- **Per-workflow memory opt-in**: workflow roles are isolated from memory by default (fresh scratch session, no percepts) — a stage can opt in via `use_memory: true` in its YAML definition, threaded through an optional `workflow.MemoryAwareTurnRunner` capability interface (mirrors `imagePartReceiver`) rather than widening the base `TurnRunner` interface.
- **Multimodal input, one pipeline** (ADR-0074, `cmd/milk/acp_media.go`, `attachments.go`): images enter through a single `PendingAttachment` shape on every host — TUI clipboard/`/attach`/`@file` and ACP `session/prompt` content blocks (bare-base64 `image` blocks with `mimeType` per spec, sniffed when absent; `audio`/unknown block kinds degrade to a visible notice, never a dropped prompt) — and ride ctx-carried parts (`local.WithImageParts`, issue #297 discipline) gated by the agent's `vision: true`. claude-cli turns stage `@/tmp/milk-img-*` refs from the runners (`stageCLIImageRefs` — alive across self-escalation, cleaned at turn end); Bedrock Converse and Responses transports carry image parts too; an endpoint that rejects images retries once with images stripped plus a notice instead of a raw 4xx. Session history and memory store only compact `[attached image: …]` placeholders, never base64, and background clones keep `supportsVision`.
- **Turn bounds, resolved** (issues #304/#305): the tool-iteration budget resolves `limits.max_tool_iterations` → `local_max_tool_iterations` → `max(20, context_window_tokens/4096)` → **40** when the window is unknown — that last state prints a session-start notice (TUI transcript line, ACP message chunk) suggesting `context_window_tokens` or a forced budget; `-1` = unlimited (the runner maps it to a negative sentinel the tool loop honors). `turn_timeout_secs` (600s) is an idle-refreshed advisory warning — the clock resets on streamed bytes, tool start/end and retry activity (`cmd/milk/idlewatch.go`, shared by TUI and ACP, warns once per idle stretch); `limits.turn_deadline_secs` is the opt-in hard bound (forced closing summary with tools disabled first, hard stop only after a grace period); the fixed 10-minute constant in `turn_routing.go` bounds only the routing/classifier step (`routing timeout`).

## Session states

```text
ROUTING          → LOCAL | ESCALATION
LOCAL            → ESCALATION (on --escalate or escalate())
ESCALATION       → ESCALATION_WAITING (when escalation agent asks a question)
ESCALATION_WAITING → ROUTING (on --primary)
ESCALATION_WAITING → ESCALATION (default: next turn goes via --resume)
```

### Sticky mode (`/escalate` / `/primary` without a prompt)

Typing `/escalate` alone (no inline prompt) sets `stickyEscalate = true`: every subsequent turn is routed to the configured escalation agent, bypassing the router, until the user types `/primary` or presses Ctrl+C. The prompt label shows `<agent> (pinned)`.

Symmetrically, `/primary` alone sets `stickyPrimary = true`: every turn goes to the primary agent until `/escalate` or Ctrl+C. The prompt label shows `<agent> (pinned)`.

Typing `/escalate <prompt>` or `/primary <prompt>` is a **single-turn override** (`forceEscalate` / `forcePrimary`): the flag is reset to false after the turn completes, and normal routing resumes.

### Auto-sticky escalation

When the router first escalates (without an explicit `/escalate`), `autoStickyEscalate` is set automatically — every subsequent turn stays on the escalation agent, showing `<agent> (sticky)` in the status bar. This avoids the "RETURNING" context-mode where Claude would otherwise lose continuity between sessions. Cleared by `/primary` or a single-turn `forcePrimary` override.

Disable via `sticky_escalation: false` in `~/.milk/config.json`. Explicit `/escalate` (pinned) is unaffected by this setting.

## Routing order (per turn)

1. Explicit flags (`--escalate`, `--primary`)
2. Session state (`ESCALATION_WAITING` → bypass)
3. Rules layer (hard thresholds → short-prompt shortcut → weighted signal scorer)
4. Local model (classification call, when scorer is inconclusive)
5. Default: local

## Session storage

```text
~/.milk/sessions/index.json        # cwd → [{id, name, last_used}]
~/.milk/sessions/<uuid>.json       # full session (history, state, escalation_session_id)
~/.milk/sessions/<uuid>.history    # per-session input history (plain text, one entry/line)
~/.milk/input_history              # global input history across all sessions
```

Default behavior: resume most recent session for cwd. `--new` creates a fresh session.

## Token tracking: subagents and workflows

When the escalation agent (Claude Code) spawns subagents via the Agent tool or runs background workflows, milk tracks their token usage separately from the main process. This applies to:

- **Subagent tokens** — subagents spawned by Claude Code's Agent tool
- **Workflow tokens** — background workflows run by Claude Code

### Agent role strings

Token usage is stored in the session `Tokens` map keyed by `"model\x00role"`. The role strings follow this convention:

| Role string | Meaning |
|---|---|
| `primary` | Local agent (router + local model) |
| `escalation` | Main escalation agent (Claude Code) |
| `escalation:subagent` | Subagent spawned by the escalation agent |
| `escalation:workflow` | Background workflow run by the escalation agent |
| `primary:subagent` / `escalation:subagent` | `spawn_background_agent` job (ADR-0043), tagged by the spawning agent's own role — the same suffix as Claude Code's subagents, but recorded directly by milk rather than parsed from a subprocess's stream JSON |
| `user:subagent` | A background job the *user* spawned directly (pressing Enter again while busy — see ADR-0043's TUI section), not an agent's own tool call — there is no agent role to tag it with, so it gets its own bucket rather than being miscategorized under `primary` or `escalation` |

The colon-separated convention allows prefix queries — `SessionTokensByRolePrefix("escalation")` matches all escalation-related roles (main turns, Claude Code's own subagents/workflows, and any spawn_background_agent jobs an escalation-role local agent ran).

### How it works

1. `stream.go` parses `SubagentUsage`/`WorkflowUsage` from the `result` event's stream JSON when present.
2. `dispatch.go` records these via `sess.AddTokensFull` with the appropriate role string and via `obs.RecordTokens` / `obs.AccumulateCacheTokens` for OTel metrics.
3. `FormatTokenUsage` in the TUI displays each role string as its own row in the `/usage` table.
4. The eval harness (`adapter_claude.go`) captures subagent/workflow tokens from the transcript JSONL.
5. Graceful degradation: when Claude Code does not provide subagent/workflow data, all tokens are attributed to the main `escalation` role as before.
6. `spawn_background_agent` jobs (ADR-0043) follow the same `<role>:subagent` convention but are recorded directly by `dispatch.go`'s `drainBackgroundJobs` when a job completes, not parsed from anything — see [docs/adr/0043-background-subagents.md](docs/adr/0043-background-subagents.md).

## Loop detection

Milk detects when an LLM agent gets stuck in a loop — repeating the same phrase/tool-call within a turn, or producing identical responses across turns. This prevents runaway token consumption when the user doesn't interrupt. Five complementary systems work together:

### Agent-internal detectors (`internal/agent/local/`)

| Detector | Catches | Recovery |
|---|---|---|
| **Streak tracker** (`loop_streak.go`) | Same reasoning hash or tool-call signature across consecutive iterations | Crop + nudge → strong nudge → terminate |
| **Streaming n-gram** (`reasoning_ngram.go`) | Periodic reasoning repetition during streaming | **Cuts stream immediately** + nudge → strong nudge → terminate |
| **Text-loop tracker** (`loop_streak.go`) | Same output text across consecutive steps | Crop + nudge → strong nudge → terminate |
| **Duplicate tool calls** (`local.go`) | Model re-issues a tool call already executed while nothing changed in between (read-only calls never count in a mixed batch; a pure read-only batch is flagged only after 3 identical executions; any file write *or bash call* resets the memory — issue #256) | Nudge → strong nudge → terminate |
| **Doom-loop gate** (`local.go`, `loop_streak.go`) | 3 *consecutive* iterations issuing the exact same tool-call batch (stronger signal than "duplicate tool calls," which fires on any repeat seen anywhere earlier in the turn, not just back-to-back) | Interactive permission ask → continue if approved, or fail closed (deny) — not a nudge; treated as a safety event, since a model that repeats identically 3 times *in a row* has already ridden out whatever self-recovery the other detectors offer |

Escalation mechanics (crop → mild nudge → strong nudge → terminate) are consolidated in one shared helper (`loopRecoveryAction` in `loop_streak.go`) called by the first four detectors, rather than each re-implementing it — this is what fixed the text-loop tracker's termination path above, which previously had no working counter of its own. The doom-loop gate is deliberately separate: it's not a self-recovery nudge ladder, so it doesn't go through `loopRecoveryAction`. The crop removes only the last N tool-calling iterations the detector actually saw repeating (`cropGroups`: the trigger count for the streak and text-loop trackers, **0** for the duplicate-call and n-gram detectors, whose repetition is not in the message list yet) — an earlier 64-message crop erased most of a long turn's reads on a single repeated `go build`, and the model then re-read everything. The duplicate-call detector also forgets earlier calls once a batch may have changed the world (`resetExecutedKeysAfterStateChange` — file writes and any `bash` call, whose effects are opaque), so re-running a build/test/diff after an edit — or a pre-merge check batch after a `gh pr merge` — is not a "repeat".

**Workflow-role scoping**: when an agent is executing a workflow step (`workflowRole == true`), the streak tracker, streaming n-gram, and text-loop tracker are all skipped — reasoning and output text legitimately repeat across workflow passes, and the workflow interpreter (`internal/workflow/interp`) handles recovery for those at a higher level (see `isTerminatedTurn`). Duplicate tool calls and the doom-loop gate are **not** skipped for workflow role: a literal repeat of a write-tool call with identical arguments has no legitimate cross-pass explanation, so it's caught early regardless of caller — the doom-loop gate specifically fails closed for a workflow step (no one to ask), instead of the interactive permission prompt an ordinary turn gets. Critically, the n-gram monitor's mid-stream *feed* is gated by workflow role too, not just its Run-loop recovery handling — feeding it and ignoring the trigger would still cut every subsequent stream in the turn with no recovery, since the monitor's window is never reset.

**Budget-exhausted vs. loop-terminated** (workflow steps only): a step that simply runs out of tool-call iteration budget (no forced-summary nudge fires for workflow roles at the last iteration, unlike ordinary turns) produces a distinct `iterationBudgetExhaustedMarker`-prefixed message, checked by the interpreter's `isBudgetExhaustedTurn` *before* the generic `isTerminatedTurn` check. Both currently advance the workflow the same way ("break" with partial output), but get different trace outcomes and transcript messages — a budget-exhausted step is not reported to the user as "terminated by loop detection," since it may simply have needed more iterations, not evidence of a stuck loop.

### TUI-level signals (`internal/loop/detector.go`)

| Signal | Scope | What it catches | Default threshold |
|---|---|---|---|
| **chunk_repetition** | Intra-turn | Same text repeating in streaming output (consecutive, or scattered for chunks ≥40 runes) | 5 occurrences in 50-chunk window |
| **reasoning_chunk_flood** | Intra-turn | Too many reasoning chunks with no content output or tool call since the last progress (both reset the accumulation) | 5000 chunks |
| **token_velocity** | Cross-turn | Rapid token consumption without progress | 300k tokens in 60s window |
| **silent_burn** | Per-turn | High input tokens, near-zero output | 20k input tokens |
| **turn_flood** | Session | Excessive turns without user input | 10 consecutive non-user turns |

Note: consecutive reasoning chunk repetition was removed from TUI signals — now handled by the streaming n-gram detector which cuts the stream immediately.

**Observability**: the four agent-internal recovery-ladder detectors and the doom-loop gate (not the TUI-level signals above) emit a `milk.loop.recovery` OTel counter on every crop/nudge/terminate/doom-loop decision, tagged with low-cardinality `model`/`agent`/`detector`/`outcome` attributes only — deliberately *not* `session_id` (unbounded cardinality would make the counter's time series grow forever). The same detectors' plain-text `slog` lines (`internal/obs`'s `milk.log`, via `(*Agent).logWarn`) *do* carry `session_id` (and `job`, for background jobs, via the pre-existing `jobAttrs`) — fine for a rotated text log, and the attribution a prior manual investigation (`docs/internal/analysis/session-2026-10-01-primary-overload-analysis.md`) had to reconstruct by hand from timing/model fields alone. See `docs/internal/plans/escalation-and-context-enhancements-plan.md` Track B Phase 1 for the full rationale.

### How it works

1. **Streaming n-gram**: During reasoning streaming, every `reasoning_content` delta feeds a sliding 1000-token window. Two independent checks run: a block of 4+ tokens repeating 5+ times **consecutively** (verbatim back-to-back loop — an unambiguous signal, so the threshold is low), or any 4+ token block recurring 20+ times **within a 200-token span** anywhere in the window (a weaker, "thinking in circles" signal — a phrase can legitimately recur many times across a long analysis, so it needs more repetitions bounded by distance before it counts as a loop). Either check cuts the stream immediately and injects a recovery nudge.
2. **Streak tracker**: After each tool-calling iteration, the reasoning text (truncated to 500 chars, normalised) is hashed. Three consecutive identical hashes trigger crop + nudge.
3. **Duplicate tool calls**: After each iteration, tool calls are checked against previously executed calls. Exact matches trigger a nudge (not termination), similarly to MiMo-Code's approach (an independent implementation compared during a 2026-09-29 review, not a port — see docs/internal/analysis/prompt-context-management-review.md).
4. **Doom-loop gate**: A separate, independent tracker compares each iteration's full tool-call batch signature (order-sensitive, exact-match) to the immediately preceding iteration's. On the 3rd consecutive match, raises a `doom_loop` permission ask through the same interactive-ask plumbing ordinary tool permissions use — approving resets the streak and lets the model continue; denying, or having no one to ask (background job/workflow role), terminates the turn immediately.
5. **TUI-level**: `FeedChunk()` is called for every streaming chunk. A ring buffer tracks the last 50 chunks. Cross-turn signals fire after each turn completes.
6. **Status bar**: Shows `[⚠ loop — auto-interrupted]` / `[⚠ consumption — auto-interrupted]` on an auto-interrupt, or `[⚠ <category>: <message>]` for warn-only signals.
7. **Transcript**: Shows `[⚠ loop detected: …]` for repetition-based loop evidence and `[⚠ consumption: …]` for consumption/volume threshold crossings (`reasoning_chunk_flood`, `token_velocity`, `silent_burn`, `turn_flood`). No numeric confidence percentage is rendered anywhere — the internal severity score is a fixed per-signal constant, not a measured probability (issue #173).
